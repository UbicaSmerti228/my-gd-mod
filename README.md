# ILL Replay Bot

Geode-мод для Geometry Dash 2.2081 (Windows): реплей-бот для шоукейсов уровней из Impossible Levels List.

## Как работает
- Нажатия записываются по **номеру тика физики**, а не по кадрам и не по времени. Просадки FPS во время записи видео не сбивают макрос.
- Запись можно вести на замедленной скорости (слайдер Speed), воспроизводить на x1.00.
- В режиме практики после респавна на чекпоинте запись обрезается до этого места.
- На экране метка `BOT REC` / `BOT PLAY` с измеренным TPS (нужна для отправки в ILL).
- Пока бот включён, уровень идёт в test mode: прогресс, звёзды и прохождения **не сохраняются**.

## Использование
1. Поставь [Geode](https://geode-sdk.org), скачай `.geode` из артефакта сборки в GitHub Actions и положи в папку `geode/mods` игры.
2. В уровне открой паузу и нажми фиолетовую кнопку **BOT**.
3. **Record**, перезапусти уровень и проходи. Потом впиши имя и нажми **Save**.
4. **Play** (выбери реплей в списке), перезапусти уровень. Бот проходит сам, твои клики игнорируются.

Реплеи лежат в папке сохранений мода (`replays/*.ilr`), кнопка **Folder** её открывает.

## Анализ окон кадров (как у NaN)
Кнопка **Analyze windows** в меню бота (нужен загруженный реплей этого уровня). После неё сними паузу: анализ идёт прямо в уровне, звук на это время выключается.

- Для каждого нажатия и отпускания бот берёт чекпоинт чуть раньше, сдвигает инпут на ±1, ±2… тика и прогоняет уровень потиково, не трогая остальные инпуты. Сдвиг считается рабочим, если игрок выжил до следующего инпута плюс 10 тиков или вернулся на эталонную траекторию. Отсюда **окно**: сколько тиков подряд клик срабатывает.
- Перед перебором несдвинутый клик прогоняется с того же чекпоинта. Если он не повторяет эталон, клик помечается **ненадёжным** (маркер `?`) и в счётчик и L* не идёт.
- Результат сохраняется в `.ilr` вместе с реплеем (кнопка **Save**).

При воспроизведении (**Play**) после анализа:
- слева сверху счётчик `9-12 / 7-8 / 5-6 / 4 / 3 / 2 / 1` в цветах NaN, со вспышкой и звуком на каждый клик;
- кольца с размером окна на месте каждого клика;
- слева снизу доля сложности уровня (%) и текущий **L*** по формуле NaN (порт из [Frame Window Counter](https://github.com/hyper-5/frame-window-counter), MIT);
- справа сверху `текущий/макс/всего CPS`;
- траектории: пройденный путь, будущий путь (пунктир) и веер всех проверенных вариантов для ближайших кликов (цвет категории — выжил, красный с крестиком — смерть).

### КБФ-счётчик (Click Between Frames)
С CBF клик срабатывает не на границе тика, а в любой момент внутри него, поэтому окно — дробное число кадров. После поиска в целых тиках анализатор для каждой границы окна (последний рабочий тик ↔ первый смертельный) делает бинарный поиск по моменту клика внутри тика: шаг физики делится так же, как в моде [Click Between Frames](https://github.com/theyareonit/Click-Between-Frames) (MIT). Точность 1/16 тика. Получается ширина вроде `3.44` или `0.61`: frame-perfect клик на деле может быть уже или шире одного кадра.

Переключатель **CBF** в меню показывает и считает L* по дробным окнам (выключен — по целым тикам). Если сторона окна упёрлась в соседний клик той же кнопки, а не в смерть, её край считается за полтика.

Свои звуки: положи `fw-9-12`, `fw-7-8`, `fw-5-6`, `fw-4`, `fw-3`, `fw-2`, `fw-1` (`.ogg`/`.mp3`/`.wav`) в папку конфигурации мода, подпапку `sounds/`.

## Ограничения
- Physics bypass (TPS выше 240) мод не делает. Если нужен, ставь отдельный мод; бот считает тики сам и запоминает TPS записи.
- Уровни с random-триггерами могут расходиться: сид рандома не фиксируется.
- Анализ использует чекпоинты режима практики. Если игра восстанавливает с чекпоинта не всё (некоторые триггеры), такие клики помечаются ненадёжными, а не считаются неправильно.
- Веер траекторий хранится только в памяти: после перезапуска игры видны счётчик и L*, веер появится после нового анализа.
- Процент под счётчиком — это моя трактовка (доля −log вероятности прохождения при итоговом L*). Точной формулы процента NaN я не нашёл.
